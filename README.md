# Counterpoint

A bull agent and a bear agent argue a crypto token using RYO-CHAN's live, read-only market research tools. A judge weighs the evidence and reaches a verdict. Built for the [RYO-CHAN Hackathon 2026](https://ryobuild.com) — Track 1 (Autonomous Agents) and Track 2 (Dashboards & Interfaces).

## Why this design

Every claim the bull and bear agents make is derived directly from a named field in RYO's response — RSI(14), confluence gates, catalysts, risks, 7-day Fear & Greed shift, and RYO's own preview trade plan. Nothing is generated by an external LLM and nothing is invented: the same market data always produces the same debate, and every line in the trail can be traced back to `tool.field = value`. This was a deliberate choice to satisfy the hackathon's core rules — no fabricated data, a repeatable reasoning trail, and "coping with failure" when a tool is slow, partial, or unavailable.

## What it does

1. You enter a symbol (`SOL`, `BTC`, `AVAX`, …).
2. The server calls `analyze_token`, `deep_analysis`, and `monitor_market_sentiment_shift` in parallel.
3. The bull agent and bear agent each build a list of weighted claims from the structured data.
4. A judge compares the weighted scores. If they're close, it falls back to RYO's own model verdict as a tie-break anchor; otherwise it declares bullish/bearish with a confidence level, and notes whether that agrees with RYO's own verdict.
5. The dashboard shows the verdict and score first (readable in seconds), the two cases side by side, and an expandable full reasoning trail underneath.

## Known constraint

RYO's `deep_analysis` tool genuinely takes 30–40 seconds per call (verified against the live API, not a fluke of a cold start). The UI sets that expectation up front rather than hiding it. If `deep_analysis` or the sentiment call fails or times out, the debate still runs on `analyze_token` alone and surfaces a warning instead of crashing — this is deliberate, not an oversight.

## Setup

```bash
npm install
cp .env.example .env.local   # fill in RYO_MCP_URL and RYO_MCP_CREDENTIAL
npm run dev
```

`RYO_MCP_CREDENTIAL` must never be committed — `.env.local` is git-ignored, only `.env.example` (with empty values) is tracked.

## Stack

Next.js (App Router) + TypeScript + Tailwind. No external LLM API — the reasoning engine is deterministic TypeScript in `src/lib/debate.ts`. RYO's REST surface is wrapped server-only in `src/lib/ryo.ts`.
